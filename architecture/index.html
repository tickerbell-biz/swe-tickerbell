System design

One ecosystem. Clear service boundaries.

GitHub remains the source of truth. Google services host and run the application. Auth0 identifies users. The API makes every sensitive authorization decision.

Protected request flow

1. User signs in
2. Auth0 issues token
3. Browser calls API
4. API verifies role
5. Data is returned
Security boundary: hiding a button is user-interface behavior. The Cloud Run API must independently verify the token, role, ownership, and requested operation.

Non-negotiable rules

  • No Auth0 client secret, API key, service-account key, password, or customer data in GitHub.
  • Use GitHub-to-Google workload identity rather than long-lived deployment keys.
  • Give the Cloud Run service account only the Firestore and Storage permissions it needs.
  • Store protected PDFs in a private bucket, never in the public frontend repository.
  • Record admin changes in an audit log.

Implementation phases

  1. Run this frontend locally and review the page structure.
  2. Create Auth0 tenant and connect login/logout.
  3. Deploy frontend preview to Firebase Hosting.
  4. Create private FastAPI backend and one protected profile endpoint.
  5. Add Firestore learner profile and progress documents.
  6. Add team content operations and admin analytics.
